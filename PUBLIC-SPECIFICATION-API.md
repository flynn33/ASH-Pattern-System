# Public Specification API

APS 1.0 defines state, codeword, orbit, realm, transition, topology, diagnostic, recovery, fallback, generation, schema, canonical data, and conformance surfaces as its public specification API.

## 1.0.0-rc.3 normative reconciliation

This release records an explicit precedence decision for internal reference drift. The specific 1.0 core and algorithm contracts below, together with their versioned canonical data, define the current model. Earlier generic module-contract, invariant, and registry wording is retained for provenance; conflicting clauses listed here are superseded, not alternate implementation choices. Unaffected requirements remain binding. This decision preserves the existing operational-context and structural-topology model and all locked mathematics.

| Concern | Current normative source and meaning | Superseded wording |
|---|---|---|
| Structural state normalization | `specs/core/state-admissibility.pseudo.md`: parse exactly nine binary coordinates and preserve every bit, realm, and orbit. Every well-formed vector is a realm; malformed input produces a diagnostic before a state exists. | `state-model-contract.md` normalization-to-valid/correction clauses and `INV-STATE-003` transformation-incompatible normalization failure. The invariant now requires malformed-input rejection, not rejection of any well-formed realm. |
| Operational assessment and recovery | `specs/core/system-state-classification.pseudo.md`, `specs/core/recoverability-semantics.pseudo.md`: validated context and runtime mode determine the seven classes. Categories are `NO_ACTION`, `TARGET_RESOLUTION_REQUIRED`, `APPLY_CORRECTION`, `FALLBACK_REQUIRED`, `CONTAINMENT_ACTIVE`, `EXTERNAL_ESCALATION_REQUIRED`, `TERMINAL_NO_RECOVERY`. Malformed input has no system-state class. | Intrinsic state-health, `VALID`/`TRANSFORMATION_COMPATIBLE`/`TRANSFORMATION_INCOMPATIBLE`/`UNCLASSIFIED` admissibility, and `NORMALIZE_STATE` recovery clauses in generic module contracts. |
| Realm identity | `specs/core/state-admissibility.pseudo.md` and `canonical-data/1.0/realms.json`: encode all well-formed nine-bit realms as `APS-REALM-000` through `APS-REALM-511`, independently of operational health. | RealmEncoder clauses that reject a structurally well-formed state merely because it lacks a health classification, and the earlier open-format note in `realm-identity.pseudo.md`. |
| Topology | `specs/algorithms/branching-semantics.pseudo.md`, versioned topology corpus, and `tools/product/aps_product.py::topology_result`: root `R`, ordered `C/P/N` children, `APS-NODE-` IDs, all nodes through requested depth plus leaves, stable `(depth,generation_ordinal)` order. No implicit state mutation. Optional branch-state profiles must name explicit canonical transitions. | State-derived topology requirements in `topology-generator-contract.md` and the older `F` seed/leaf-only pseudocode in `topology-expansion.pseudo.md`. |
| Fallback | `specs/algorithms/recovery-fallback-semantics.pseudo.md` and `canonical-data/1.0/fallback-policy-definitions.json`: policy 001 orders configured rank then realm ID; policy 002 orders descending verification sequence then realm ID; policy 999 escalates without replacement. Candidates come from validated downstream instances. Immediate reassessment accepts the algorithm's `STABLE`, `CORRECTABLE`, or `UNSTABLE` classes. | Generic rank-then-policy-ID ordering, hardcoded registry candidate states, and STABLE-only fallback reassessment in the older registry/module prose. Correction remains a distinct same-orbit codeword action with post-checks. |
| Diagnostic shape and safety | `specs/interfaces/diagnostic-schema.md`: full fifteen-field record, meaningful notes, nine-field semantic digest, explicit causal safety phases, complete chain checks, and frozen terminal finality. `rule-id-taxonomy.md` permits registered short IDs and declared long IDs. | Seven-field/empty-note rc.1 corpus and the long-ID-only `INV-DIAG-002` test criterion. |
| Axiom evidence | `specs/algorithms/axiom-evaluation.pseudo.md` fixes the five complete-measurement predicates; `conformance/1.0/vectors/axioms.jsonl` additionally requires `INDETERMINATE` when profile-required measurement is absent. Preserve those predicates unchanged and diagnose missing evidence instead of fabricating Boolean measurements. | A Boolean-only result treated as complete when required evidence is absent. |
| Generation profiles and identity | `specs/algorithms/generation-planning.pseudo.md` and `conformance/1.0/vectors/generation-plans.jsonl`: the downstream implementation owns a documented registry of supported profile/naming/target references. Unknown profile fails with `PROFILE_REFERENCE_INVALID`; identical requests with identical registries/policies have stable plan identity; changing a bound registry version changes identity. Include all behavior-affecting request and registry identities in the documented hash payload. | Accepting arbitrary profile strings or reporting stable identity while omitting behavior-affecting registry versions. No canonical `DEFAULT`/`BASELINE` profile names or hash wire format are invented here. |

These named clauses are compatibility corrections within the prerelease series. They do not change the canonical codeword set, bit order, XOR, realm/orbit identity, averaging operator, existing operational classification predicates, or fallback definition data. Schemas enforce shape and nonblank explanation fields; semantic validation still owns identity, chain continuity, safety phases, and actual explanatory meaning.
