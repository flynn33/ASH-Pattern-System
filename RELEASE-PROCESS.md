# Release Process

From a clean checkout, run `python3 tools/product/verify_canonical_data.py`, `python3 tools/product/verify_conformance_corpus.py`, `python3 tools/product/build_release_archive.py --source-commit <release-source-commit> --verify`, `python3 tools/product/verify_release_archive.py --archive release/ash-pattern-system-1.0.0-rc.3.zip`, and `python3 tools/product/release_readiness.py --strict --offline --source-commit <release-source-commit>` before publishing.

For an exact committed source snapshot, create an external verification copy of the clean checkout, preserving source bytes and excluding `.git` and interpreter caches. Supply the actual source commit explicitly. Stamp that copy's product manifest to the source commit, build its archive with `--verify`, verify the archive, and run strict offline readiness in the copy. This avoids a self-referential source SHA in the tracked manifest: the source checkout's manifest is generation metadata, while the staged/archive manifest binds the actual released commit. Preserve historical release archives and their manifests; never overwrite a prior tag or qualification cache. The current archive builder emits the current product version's name and preserves the existing LICENSE without reintroducing the removed LICENSE.md.
